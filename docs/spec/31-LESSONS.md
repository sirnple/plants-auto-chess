# 31-LESSONS.md - 设计经验教训

## 设计决策记录

### 1. 合成系统：循环合成设计

**问题描述**: 最初设计合成系统时，只考虑了一次合成。实际测试发现，有6个1星植物时，只合成1个2星，剩下3个1星没有继续合成。

**分析**: 玩家期望一次操作完成所有可能的合成（6个1星 → 2个2星）。

**解决方案**: 
- 使用循环合成设计
- 一次检查中持续合成，直到没有可合成为止
- 例如：6个1星 → 合成2个2星 → 继续检查 → 3个2星 → 合成1个3星

**设计原则**: 
- 合成应该是"贪婪"的，尽可能完成所有合成
- 减少玩家操作次数

---

### 2. 商店系统：满员购买设计

**问题描述**: 备战席满了（8个）时，玩家希望能购买第9个植物并触发合成。

**分析**: 如果满员就不能购买，玩家需要手动卖出植物，体验不好。应该允许"先买后合"。

**解决方案**: 
1. 添加预检查机制：判断购买后是否能触发合成
2. 如果满员但能合成，允许购买
3. 购买后触发合成，备战席不会溢出

**关键逻辑**:
- 预检查时模拟添加植物
- 检查模拟后的备战席是否有3个可合成
- 实际添加时正常放入空位，然后触发合成

**设计原则**:
- 优先考虑玩家体验
- 减少不必要的限制

---

### 3. 备战席：固定8格设计

**问题描述**: 早期设计考虑动态扩容，导致合成后备战席长度超过8。

**分析**: 
- 动态扩容导致UI布局困难
- 玩家对固定8格的预期更清晰
- 合成后植物应该放在空出的槽位

**解决方案**:
- 备战席固定8个位置
- 合成时3个植物销毁，1个新植物放在第一个空位
- 保持备战席长度不变

**设计原则**:
- 固定数值比动态数值更容易理解和维护
- UI布局应该基于固定尺寸

---

### 4. 信息查看：信息模式设计

**问题描述**: 最初设计使用右键显示植物信息，但体验不好。

**分析**:
- 右键可能触发浏览器上下文菜单
- 不符合自走棋游戏习惯
- 需要明确的状态提示

**解决方案**:
- 添加"信息模式"切换按钮
- 点击切换后，左键点击植物显示信息
- 信息面板4秒后自动消失

**设计原则**:
- 交互设计要符合用户习惯和平台特性
- 明确的状态反馈（按钮高亮）
- 避免与系统默认行为冲突

---

### 5. UI布局：分区设计

**问题描述**: 初始布局元素重叠、超出边界、位置混乱。

**分析**:
- 没有统一规划各区域
- 各组件独立定位，没有考虑整体

**解决方案**:
- 重新规划布局：战场左侧，控制面板右侧，备战区底部
- 明确各区域坐标范围
- 统一使用相对位置

**最终布局**:
- 顶部：状态栏（阳光、生命、回合、信息模式按钮）
- 左侧：战场区域（50-610px宽度）
- 右侧：商店、羁绊、按钮（x=980px）
- 底部：备战区（y=720px）

**设计原则**:
- UI设计要先画草图，确定布局后再实现
- 各区域应该互不重叠
- 考虑视觉重心和操作便利性

### 6. 星级设计：最大4星

**问题描述**: 最初设计最大3星，玩家希望有更高星级的追求。

**分析**:
- 3星已经是1星属性的2.25倍，很强力
- 但4星可以提供更高的成就感
- 需要平衡4星的难度和收益

**解决方案**:
- 最大星级设为4星
- 4星属性是1星的3.375倍
- 合成条件：3个3星 → 1个4星

**数值设计**:
```
1星: 100%
2星: 150% (×1.5)
3星: 225% (×2.25)
4星: 337.5% (×3.375)
```

**设计原则**:
- 提供长期追求目标
- 高难度应该对应高收益
- 4星应该是 rare 的，不是每局都能达成

### 7. 羁绊设计：阈值梯度

**问题描述**: 羁绊激活条件应该如何设计？

**分析**:
- 线性递增（2/4/6/8）太平淡
- 需要有明显的强度跳跃
- 考虑实际游戏中能达到的数量

**解决方案**:
- 射手系：2/3/5（5个是极限挑战）
- 防御系：2/3/4（相对容易达成）
- 阳光系：2/4（经济羁绊，门槛较低）

**设计原则**:
- 不同羁绊应有不同的梯度设计
- 要考虑实际游戏中能达成的植物数量
- 高阈值应有显著更强的效果

## 最佳实践总结

### 1. 实体与系统分离
- Entity 只负责自己的属性和表现
- System 负责管理和协调多个 Entity
- 避免 Entity 直接访问其他 Entity

### 2. 事件驱动解耦
- 使用事件机制解耦模块
- 如：僵尸死亡事件、产生阳光事件
- 避免直接调用，降低耦合

### 3. 配置与逻辑分离
- 所有数值配置集中管理
- 逻辑代码读取配置，不硬编码
- 便于平衡性调整

### 4. 边界条件测试
特别注意以下边界条件：
- 备战席满员时的购买
- 多个可合成组的同时合成
- 满星植物的处理
- 空值检查

## 设计原则总结

1. **玩家体验优先**: 减少限制，提供便利
2. **明确的状态反馈**: 按钮高亮、动画提示
3. **渐进复杂度**: 前期简单，后期有深度
4. **一致性**: 相同类型的操作有相同的反馈
5. **可预测性**: 玩家能预判操作结果
