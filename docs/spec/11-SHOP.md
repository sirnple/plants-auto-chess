# 11-SHOP.md - 商店与合成系统

## 商店系统

### 基本规则
- **商店槽位**: 5个
- **刷新费用**: 2阳光
- **锁定功能**: 可锁定当前商店（暂未实现UI）

### 购买流程
1. 点击商店植物
2. 检查阳光是否足够
3. 检查备战席是否有空间（或能否合成）
4. 扣除阳光，植物进入备战席
5. 触发自动合成检查

### 植物解锁
新植物随回合解锁：
- 回合1: 向日葵、豌豆射手、坚果墙
- 回合2: 寒冰射手
- 回合3: 樱桃炸弹、双发射手
- 回合4: 双子葵、跑酷僵尸
- 回合5: 铁桶僵尸、火爆辣椒
- ...（详见20-DATA.md）

## 合成系统

### 核心规则
- **合成条件**: 3个相同类型 + 相同星级
- **最大星级**: 4星
- **属性成长**: 每升1星，生命值和攻击力 ×1.5
- **自动合成**: 添加植物后自动检查并合成

### 星级成长示例
```
豌豆射手（1星）: 100血, 15攻
豌豆射手（2星）: 150血, 22攻  (×1.5)
豌豆射手（3星）: 225血, 33攻  (×2.25)
豌豆射手（4星）: 337血, 50攻  (×3.375)
```

### 合成流程
```
添加植物 → 分组统计 → 找出可合成组 → 执行合成 → 重复检查
```

### 关键设计决策

#### 1. 循环合成
**问题**: 第一次实现时，`checkAndMerge` 只执行一次合成就返回，导致有6个1星时只合成1个2星。

**解决方案**: 使用 `while` 循环持续检查合成，直到没有可合成为止。

```typescript
while (canContinue) {
  // 找出一组合成
  // 如果找到，继续循环（可能还能合成）
  // 如果没找到，退出循环
}
```

#### 2. 满员购买
**问题**: 备战席满了（8个）时，如果有3个可合成，应该允许购买第9个并合成。

**解决方案**:
- `canAddToBench`: 模拟检查是否能添加（包括满员但能合成的情况）
- `addToBench`: 正常添加到空位，然后触发合成
- 如果满员且不能合成，返回false

**关键逻辑**:
```typescript
canAddToBench(plant): boolean {
  if (hasSpace()) return true  // 有空位，肯定可以
  
  // 满员时，模拟添加后检查是否能触发合成
  const tempBench = [...this.bench, plant]
  return 检查tempBench中是否有可合成的组
}
```

#### 3. 备战席固定8格
**问题**: 早期实现使用 `push` 添加植物，导致合成后备战席长度超过8。

**解决方案**: 
- 备战席固定为8个位置（`Array(8).fill(null)`）
- 使用 `findIndex` 查找空位
- 合成后植物放在第一个被清空的槽位

### 实现细节

#### MergeSystem.checkAndMerge()
```typescript
方法签名: checkAndMerge(): { merged: boolean; newPlant?: Plant; index?: number }

返回值:
- merged: 是否发生了合成
- newPlant: 合成后的新植物（如果有）
- index: 新植物在备战席的位置（如果有）

逻辑:
1. 按 (type_starLevel) 分组统计
2. 找出数量>=3的组
3. 执行合成：3个删除，1个新植物放在第一个位置
4. 播放特效
5. 继续检查（可能还能合成）
```

#### 合成特效
- 植物放大缩小动画
- 金色粒子效果
- 星级文字飘升
